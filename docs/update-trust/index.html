GOVERNANCE GAP MEMO · ONE PAGE

EGF 已經定義了什麼、還沒定義什麼、我們補上什麼

依 GLEIF vLEI Ecosystem Governance Framework v4.0（Primary Document v1.2 · 2026-03-25）、GLEIF 官方訓練教材與 2026-08-25 GLEIF 部落格〈Why AI Agents Need Verifiable Organizational Identity〉整理。目標不是宣稱系統可信，而是指出流程中哪個環節有可驗證的設計、哪個環節仍是治理空白。

OFFICIAL · EGF 已定義

組織與人的信任鏈

  • 信任根：GLEIF Root AID 與 GLEIF External Delegated AID（GEDA），多位 GAR 以多簽建立；QVI 取得 QVI Delegated AID 與 QVI vLEI Credential。
  • 角色：GAR、QAR、DAR（指定 LAR）、LAR（代表法律實體申請與管理 vLEI）。
  • 憑證類型：QVI、Legal Entity、OOR Authorization、OOR（依 ISO 5009 官方職務）、ECR Authorization、ECR（法律實體自行定義的職務，可由 LE 直接簽發或由 QVI 簽發）。
  • 技術：KERI AID／KEL、ACDC＋SAID、CESR、JSON 序列化與 Ed25519 簽章、I2I 邊鏈、TEL（vcp／iss／rev）錨定於簽發者 KEL；QVI 須透過 vLEI Reporting API 回報簽發與撤銷。
  • 撤銷：由原簽發者在 TEL 記錄 rev 事件；LE vLEI 由 QAR 依 LAR 全簽請求或 LEI 失效等原因撤銷。
GAP · EGF 未定義

AI Agent 不是 EGF 裡的主體

  • OOR／ECR 的 issuee 是自然人；EGF 沒有「Agent 作為憑證持有人」的憑證類型與身分驗證程序。
  • 沒有委任語意：目的（purpose）、範圍（scope）、期限（TTL）、需本人確認的動作，都不在官方 schema 內。
  • 沒有連鎖失效規則的產品級約定：上游 ECR 或 LE 被撤銷時，下游 Agent 授權應如何、多快失效。
  • 沒有問責對映：Agent 越權時，責任落在委任的 ECR 持有人、法律實體還是平台，需要治理框架與契約補齊（GLEIF 2026-08-25 部落格亦指出「accountability behind it remains unclear」）。
PROPOSAL · 本專案補上

Agent Delegation ACDC 與碳足跡 VC（提案，非 GLEIF 官方）

  • 選擇性揭露：碳足跡 VC 依 ACDC most-compact SAID 規則，product／carbon／process／audit 各自 SAID 化；出示時 process 只剩 SAID，驗證方仍能重算 a.d 與 d。這正是痛點 1「只揭露碳排那一項，不外洩製程機密」的密碼學實作。
  • 鏈結：邊 role → ECR/OOR 使用官方 I2I 運算子，簽發者必須是有效角色憑證的 issuee；schema SAID 由本頁 JSON schema 自我定址計算。
  • 最小授權：a.purpose、a.scope.allow／deny／confirm、a.expires（預設 10 分鐘）、a.disclosure=MINIMUM_NECESSARY。
  • 可撤銷：委任有自己的 TEL registry；驗證方每次請求都重走整條鏈，任何一層 rev、過期、SAID 不符或 root 不符都回 DENY_* 與 tool_execution=false。
  • Agent 身分：Agent 自己的 KERI AID（本頁以 WebCrypto 產生 icp 事件並簽章），未來可用 KERI 委任 AID＋DI2I 運算子，讓「Agent 是持有人的委任者」在協定層可驗。
POLICY · 給政府與產業的建議

把「代理」補進台灣的第三段路

  • MyData 解決取得、數位憑證皮夾解決出示；代理需要可驗證的委任憑證，回答「誰授權、範圍多大、多久失效、出錯誰負責」。
  • 驗證方（政府機關、銀行、品牌商）應公布 schema allowlist 與 root of trust 政策，並以 fail-closed 為預設，如同本頁的 production root 切換。
  • 把 撤銷時效 寫進規範：下游授權的 TEL 狀態查詢頻率、上游撤銷後的最長容忍時間。
  • 與 GLEIF／QVI 合作，將 Agent 委任納入 EGF 的 ECR 擴充或 Trust Assurance 討論，而非各平台自建互不相認的授權格式。
